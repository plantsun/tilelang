# Fragment Replication 包含性修复

## 问题与修复范围

`ProveFragmentContains` 需要证明每个合法逻辑坐标上，小布局的所有线程都能访问大布局中的对应元素。当大布局的线程映射为完全复制形式时，原有快速路径直接返回兼容，跳过了线程覆盖和可选的物理槽位比较。

修复保持在布局包含性检查内：

1. 在所有快速路径之前执行调用方要求的物理槽位比较。
2. 绑定小布局的复制坐标，计算实际的线程映射；使用线程范围起点将该映射转换到大布局的归一化线程坐标。
3. 对完全复制的大布局，证明每个小布局线程都在大布局的复制范围内；存在绑定线程范围时，也要证明其落在该范围内。
4. 无法证明包含时返回 `false`。非完全复制布局仍走原有逆映射检查；归约 lowering 和 AllReduce 安全检查不作修改。

大布局的完全复制线程映射是 `_rep`，因此在其有效范围内覆盖连续线程。证明使用的是小布局的实际线程表达式，而不是比较两个复制数或假设小布局连续。对于分析器无法证明的符号条件，结果保守地表示“未证明”，不意味着已经证明不包含。

## 回归验证

包含性测试直接调用编译器函数，覆盖线程集合、物理槽位、非连续映射、非零和未绑定的线程范围、线程范围窄于复制映射，以及带符号逻辑坐标的部分复制布局。另有 216 组静态参数与独立枚举的物理线程集合逐项对照。

| 检查 | 未修改基线 | 修复后 |
| --- | --- | --- |
| 包含性回归 | 8 失败，10 通过 | 18 通过 |
| Layout 套件 | 298 通过、4 跳过、2 失败 | 316 通过、4 跳过、2 失败 |
| Reduction 套件 | 142 通过、13 跳过 | 142 通过、13 跳过 |

Layout 套件中两项失败在基线和修复后完全相同：用例需要的 PDL 功能在 A100 上不可用。它们不属于包含性修复新增的失败。

原有非 2 次幂归约测试的输出读取已限定在实际拥有该结果的线程上，使布局检查能够通过，并保留原有归约安全诊断的断言；该测试仍验证原有的拒绝行为。

## 端到端影响

使用 A100、FP32 和 128 个线程，对 N=64、96、100、120、127、128 分别运行 Copy、Elementwise 和 Reduce；每个成功案例对照多种输入。

| 宽度 | 修复前 | 修复后 |
| --- | --- | --- |
| 64、128 | 三类操作通过 | 三类操作通过 |
| 96、100、120、127 | Copy、Elementwise 通过；Reduce 在 lowering 阶段失败 | Copy、Elementwise 通过；Reduce 在 LayoutInference 阶段失败 |

N=96 原先在归约 lowering 的布局一致性检查处失败；修复后会在 LayoutInference 阶段排除不兼容布局，并因没有可用候选而失败。失败位置提前，但当前诊断仍是通用的“无可用布局”，不能据此声称归约问题已经解决。

显式 Warp 复制的 N=96，以及带边界保护的填充布局 N=100、120、127，均用于检查已有合法复制场景；执行结果见结构化数据。

## 后续问题

- 为不规则宽度设计通用、可证明合法的布局候选，并验证切片、填充与布局传播。
- 在布局推断无法找到候选时给出更具体的诊断。
- 继续验证不同后端、动态形状和更复杂的线程范围；分析器保守拒绝的情况需要与不兼容布局区分。

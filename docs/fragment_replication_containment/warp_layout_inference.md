# Warp 复制布局推断实验

## 目标和约束

为静态 Fragment 形状尝试通用的 Warp 复制布局，使没有显式布局标注的归约有机会得到完整线程覆盖。布局包含性检查、归约 lowering 和 AllReduce 安全约束保持不变。实验使用 A100、FP32 和 128 个线程。

## 候选与约束传播

N=96 的原始推断中，Copy 的并行循环分区提出 `thread = j`、`slot = 0`、复制数为 1 的输入布局。归约推导出的标量覆盖 96 个线程；输出 Copy 则需要标量覆盖 128 个线程。三个不同根节点的原有尝试均在归约布局包含性检查处失败，因此没有可评分的方案，并非被成本模型淘汰。

对于符合条件的 Fragment，Free Inference 可以尝试按展平逻辑坐标 `k` 构造候选：

```text
thread = warp_size * replica + k % warp_size
slot = k // warp_size
replica = 0 .. (thread_count / warp_size - 1)
```

N=96 使用 32 线程 Warp 和 4 个副本，映射为 `thread = 32 * replica + j % 32`，`slot = j // 32`。它使每个 Warp 持有全部 96 个元素；归约输出布局覆盖 128 个线程。候选经完整约束传播成功后才交给成本模型评分，寄存器计数模型在该算例中选出计数为 4 的方案。

只有原有 Free Inference 尝试均失败时才探索这种候选。候选仅用于 CUDA、静态正尺寸、元素总数为 Warp 整数倍且不超过 4096、线程数为多个完整 Warp 的普通 Fragment。候选不覆盖已知布局或显式标注；别名缓冲区、特殊累加器、线程范围无法证明一致的缓冲区以及有既有累加器回退方案的组件不进入该实验路径。不同候选的可行解由现有成本模型比较；常规推断成功时不改变原有选择。

## 端到端验证

隐式布局归约针对递增值、全 1 和固定种子的随机输入，与高精度参考求和比较。全 1 输入验证 N=96 的结果为 96，而不是把四份副本相加得到 384。显式 Warp 布局也作为对照；不兼容的显式布局保持拒绝，不被候选替换。

| 检查 | 结果 |
| --- | --- |
| 原有推断的 N=96 隐式 Reduce | 无可用布局 |
| 引入候选后的 N=96 隐式 Reduce | 三种输入均通过 |
| N=64、128、256 隐式和显式 Reduce | 均通过 |
| N=64、96、128、256 的隐式 Copy 与 Elementwise | 均通过 |
| 二维归约：3×32 沿第二维、2×96 沿任一维 | 三种输入均通过 |
| 不兼容的 N=96 显式布局 | 保持拒绝 |
| N=96 Memcheck | 0 errors |
| N=96 Racecheck | 0 hazards |

布局复制与包含性回归合计 38 项通过。Layout 套件的全量运行记录为 333 通过、4 跳过、2 失败；两项失败与包含性修复阶段相同，均涉及 A100 不支持的 PDL 功能。Reduction 套件为 142 通过、13 跳过。测试保留了三种输入和独立的数值断言，可用于重新验证线程覆盖与求和结果。算子矩阵的具体结果以结构化数据保存。

## 适用范围

该候选不处理需要填充的非整 Warp 尺寸，也没有声称解决所有不规则归约。N=100、120、127 的隐式 Reduce 仍无法通过布局推断；Padding + Guard 仍是独立原型，其自动推断需要继续研究受保护的逆映射、切片传播和越界约束。部分二维归约仍被 AllReduce 的线程步长或宽度约束拒绝，例如 2×48 沿任一维归约。动态形状、复杂线程范围、更多数据类型和后端尚需单独验证。候选只在既有推断失败时探索，因此实验结果不表示常规形状的性能提升。

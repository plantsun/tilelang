# 非整 Warp Fragment 布局与归约

## 范围与结果

对单个非单位逻辑维度的静态 Fragment，布局推断可尝试带尾部的 Warp 复制布局。128 线程、FP32 的隐式 Sum 在 N=100、120、127 均能编译并正确执行，无需显式布局标注或填充。N=96 和 N=64、128、256 继续通过。

实验使用 A100。N=100、120、127 的隐式 Sum、Min、Max 在 FP32、FP16 和 INT32 下通过正值与负值检查；Sum 另检查递增值、全 1 和随机输入。对于同一组宽度，256 线程 Sum 也通过。N=100、120、127 的隐式 Sum 通过 Memcheck 和 Racecheck，均无错误。

## 循环布局与边界

对逻辑元素 `j`，候选映射为 `thread = warp_size * replica + j % warp_size`、`slot = j // warp_size`。N=100 时，每个 Warp 的四个槽位覆盖 128 个物理位置，其中只有 100 个有效。逻辑 Fragment 的长度仍为 100。

从 Fragment 重建循环布局时，如果只传递线程映射并重新推导槽位，旧推断会得到 `j % 96 // 32`：逻辑元素 0 和 96 映射到同一线程及槽位。保留来源 Fragment 的槽位表达式可以避免碰撞。

当原推断结果无法证明单射时，布局推断尝试沿用来源 Fragment 的槽位映射。只有证明映射单射，并证明逆映射对所有合法循环坐标与副本坐标可往返时，才采用该布局；多出的物理位置由循环边界条件保护。未能证明的候选仍按原路径拒绝。线程映射逐副本相同时，包含性判断还会检查绑定线程范围，不能只根据映射表达式判定兼容。

## 复制所有权与归约尾部

归约结果布局由输入元素和复制坐标共同诱导。直接枚举原始 Fragment API 的线程集合发现：N=100、120、127 对应的复制维压缩将原有的 128 个线程缩成 `{0, 33, 66, 99}`；N=96 和 128 的压缩前后集合一致。

复制压缩先对规范化后的复制坐标尝试周期或分块符号证明；不能证明时，对有界静态布局逐项比较每个逻辑元素的压缩前后线程集合。若集合不同但原线程集合可证明具有统一的等差形式，则构造等价的压缩映射；无法证明、物理槽位依赖复制坐标或超出枚举范围时保留原布局。回归测试还覆盖分离线程组、非连续线程、大域和无法归一化的映射。

非整 Warp 归约的最终槽位可能没有写入。对于静态标量输出、单个物理槽位维度和不整除线程所有权因子的情形，归约所有权计划根据线程分割、槽位表达式和逻辑范围证明有效域；满足该入口条件但证明不足时拒绝该路径。该方法覆盖连续和交错的线程复制映射。跳过无效槽位保留归约操作自身的单位元，也避免重复累加副本；带有效域条件的路径暂不使用打包向量归约。其他显式布局的尾部语义不在该证明范围内，需要独立验证。

## 适用边界

非整 Warp 自动候选目前限于 CUDA、静态形状、最多两个维度和单个非单位逻辑维度。64 线程的 N=100、120、127，以及 2×100 的隐式 Copy、Elementwise 和两个方向的 Reduce，仍会在布局单射或逆映射阶段失败；测试记录保留这些限制。带符号尺寸、更多维度、多个非单位逻辑维度及其他后端需要进一步验证。

实验结果不表示性能提升。布局成本模型的计数也不代表实测硬件寄存器使用量。
